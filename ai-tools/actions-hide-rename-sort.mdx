The **Type** you pick when creating a customization decides what happens to your shipping methods when the rule's conditions match. There are five.

## The five types

| Type | Effect |
| --- | --- |
| **Hide shipping rates** | Removes the listed methods from checkout. |
| **Show shipping rates** | Displays the listed methods. |
| **Only show specified shipping rates and hide rest** | Displays the listed methods and removes every other option. |
| **Reorder shipping rates** | Changes the position of the listed methods. |
| **Rename shipping rates** | Changes the label shown to the customer. |

## Naming the methods

Every type asks you to list which shipping methods it applies to, under **Action**. Add as many as you need with **Add another method**.

<Tip>
  **Method names match partially.** Entering `Express` affects both "Express Shipping" and "Express Delivery". This is useful for catching a family of methods at once, but be careful — `Standard` would also match "Standard Overnight" if you have one.
</Tip>

## Hide vs. Only show

These two solve the same problem from opposite directions, and choosing well saves you a second rule.

- **Hide** is subtractive. You name what to remove; everything else stays.
- **Only show** is exclusive. You name what to keep; everything else goes.

## Show

**Show** displays the named methods without hiding anything else. It's mainly useful as the counterpart to a broad hide rule — one rule hides a method for everyone, another shows it back to a qualifying group.

## Rename

**Rename** changes only the customer-facing label. The underlying rate, its price, and its behaviour are untouched.

For each method you give the name to match and the new name to display.

### Where the new name appears

The new name shows at checkout, on the **Thank You** page, on the **Order Status** page, and on the order's details page in Shopify admin. The **Orders** list in Shopify admin keeps showing the original rate name.

<Note>
  For rates from a carrier such as UPS, Shopify adds the carrier's name in front of the new name. Renaming "UPS Standard" to "Express Shipping" shows "UPS Express Shipping".
</Note>

### Insert a cart attribute into the new name

In **parameter set 2**, a new name can include a value from the cart, such as a delivery date that your theme saves as a cart attribute. Type `{{ cart_attribute }}` where the value should go. `{{cart_attribute}}` without the spaces works too, like `{{today}}` in [rate descriptions](/rate-descriptions).

<Steps>
  <Step title="Use parameter set 2">
    On the **Conditions** card, click **Switch to parameter set 2**. Sets 1 and 3 can't read cart attributes, so they don't offer this.
  </Step>
  <Step title="Enter the cart attribute key">
    With **Type** set to **Rename shipping rates**, enter the attribute's key in **Cart attribute key** under **Action**, for example `Delivery date`. It must match the key your theme saves exactly, including capitals and spaces.
  </Step>
  <Step title="Add the placeholder to the new name">
    Put `{{ cart_attribute }}` in the new name where the value should appear, for example `Chosen Day Delivery - {{ cart_attribute }}`.
  </Step>
  <Step title="Rename only when the attribute has a value">
    Add a **Cart Attribute** condition with the same key, set to **Is not empty**. Without it, carts that don't have the attribute still get the new name, with the placeholder left blank.
  </Step>
</Steps>

**Example: show the delivery date the customer picked**

```text
Type: Rename shipping rates
Parameter set: 2
Condition 1: Cart Attribute (Delivery date) <> Is not empty
Cart attribute key: Delivery date
Rename: Chosen Day Delivery → Chosen Day Delivery - {{ cart_attribute }}
Rename: Saturday Delivery → Saturday Delivery - {{ cart_attribute }}
```

If the theme saved `Fri 13 Nov 2026 (2026-11-13)`, checkout shows **Chosen Day Delivery - Fri 13 Nov 2026 (2026-11-13)**. Carts without a delivery date keep the original names.

<Warning>
  The value is inserted exactly as your theme saves it. ShipMagic doesn't reformat dates or other values, so to show a shorter value, change the format your theme saves.
</Warning>

<Note>
  A rule reads one cart attribute. If it has a **Cart Attribute** condition, the condition must use the same key as **Cart attribute key**, or the rule won't save.
</Note>

## Reorder

**Reorder** changes which methods appear first. For each method you give the name to match and its new position.

Checkout defaults to ordering by price, which is not always what you want — the cheapest option is often the slowest, and putting it first can push customers toward a delivery experience they'll be unhappy with.<br /><br />Reordering can also help you change the default shipping option. Shopify, by default, selects the first shipping option as the default one.

## Apply rule to

Every customization also has an **Apply rule to** setting:

- **All shipments** — the default; the rule applies to every shipment in the order.
- **Only the first shipment** — for subscription sellers, so the rule affects only the first shipment's shipping method.
